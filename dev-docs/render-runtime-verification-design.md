# GVid Renderer Runtime Verification Design

**Status:** Draft test design for review. This document specifies checks to implement and run; it records no runtime pass. The [integrated design decision](render-engine-integrated-design-ReviewDecision.md) accepts the design contract only.

**Applies to:** The [integrated renderer design](render-engine-integrated-design.md), [render requirements](render-requirements.md), [flat graph/Taut design](render-graph-schema-design.md), [engine design](render-engine-design.md), [ExportJobs lifecycle](export-jobs-lifecycle-design.md), and [owner-scope contract](export-jobs-owner-scope-design.md). The exact tested commits, schema/compiler version, provider builds, and profile definitions belong in each run record, not in this living plan.

## 1. Goal and acceptance boundary

Prove that the implemented headless core produces the specified media and evidence through an offline CLI and a Glade adapter, and that the interactive path remains correct and responsive while exports run. Test actual decoding, composition, audio, encoding, probing, transport, authorization, durable jobs, process supervision and publication. The existing Python contract tests are a prerequisite, not runtime evidence.

Separate four gates so that a passing narrow test cannot be mistaken for a release pass:

1. **Contract gate:** golden Taut corpus, semantic validators and graph/editor state transitions across Python, Rust and TypeScript.
2. **Core/media gate:** real media inputs, the common planner/provider interfaces, resolver and output probe with no network service.
3. **Client/host gate:** CLI and Glade adapter against the same core; Taut control traffic and authorized HTTP media bytes; durable host and local supervisors.
4. **Release gate:** fault/concurrency matrix, provider parity, measured latency and capacity on pinned reference machines.

Each scenario below records `pass`, `fail`, or `not_run`. `not_run` never counts as pass. A supported semantic operation needs an exact reference oracle or an explicitly declared tolerance and fidelity; unsupported operations must reject. A proxy preview can be acceptable when labeled, but cannot satisfy an exact-frame or export assertion.

## 2. Harness and observability

Build one deterministic fixture generator and run manifest. The generator writes local media and Taut graph/binding/profile fixtures from checked-in seeds, records content digests and exact rational times, and offers independent expected frame/sample observations. Do not derive the expected pixels, timing or audio envelope from the renderer under test. Store only synthetic media in the repository.

The harness has five drivers around the production boundaries:

| Driver | What it exercises | Required observations |
| --- | --- | --- |
| Core driver | Validated immutable request, planner, resolver, provider, scheduler and artifact store | Task dependency ranges, chosen provider/build, cache keys, attempt IDs, bounded resource use and verification result |
| CLI driver | Fresh offline import, local/package resolver, local journal, cancellation, restart and final file | Exit/status contract, durable lookup, final file/probe and export record; no host incarnation |
| Glade driver | Authenticated Taut gateway, catalog/editor/bindings/preview/ExportJobs, host resolver and journal | Exact request/response/event envelopes, authority decisions, descriptor leases and HTTP ranges |
| Fault controller | Deterministic named barriers and process, store, resolver and provider faults | Barrier order, durable records before/after, owned processes/artifacts and recovery action |
| Media oracle | Independent decoder/probe and synthetic signal checks | Decoded frame landmarks, audio sample windows, exact timing, streams, colors and output digest |

Fault barriers must pause at named state transitions, not at arbitrary sleeps. Run both whole-tree termination and host/CLI-only abrupt death that leaves a supervised native child alive; a second process reopens the same journal and destination. Capture each child PID and creation token, and include a controlled reused-PID/different-token case so recovery cannot terminate unrelated work. Every driver records the exact request and final response class, with credentials and privileged locators redacted. Observe both state and external effects: a typed error alone is insufficient if a process still runs or a file was replaced.

The harness must be able to hold and release an event or HTTP response, advance an injected lease clock, revoke a scope, change backing source bytes and registered fingerprints between range reads, change or remove a named profile after Prepare, fail a provider, make destination equivalence unprovable, exhaust ordinary journal space, fail and later restore a write/fsync, and crash at publication boundaries. Time control may be injected at service seams; media timestamp or wall-clock calculations in production must not be replaced by test-only semantics.

## 3. Fixture set and independent oracles

Keep fixtures short enough for frequent local runs, with one longer sequence for late seek and fairness. Each fixture has a manifest of expected frame PTS, visible layers, sample windows, graph revision, binding identity, stream properties and profile definition.

| Fixture | Purpose and oracle |
| --- | --- |
| `layered-seek` | Two overlapping layers with distinct position/color/alpha marks, an implicit gap, a late-frame marker and a finite transition handle. A reference frame for each chosen time proves both layers and order; removing a layer or reversing order must fail the oracle. |
| `timing-audio` | CFR and VFR sources with nonzero PTS origin, B-frame reordering, fractional frame rate and decode preroll; mixed input sample rates and channel layouts, channel-specific tones, silence, exact gain and fade windows. An independently generated presentation-order frame ledger identifies cut-boundary frames. Probe output frame PTS, resampled channel windows, encoder delay and output A/V alignment against the ledger and a separately generated audio reference. A reordered frame, nominal-fps VFR lookup or shifted audio window must fail. |
| `asset-versions` | Same-byte new binding, changed-byte same duration, unrelated-slot rebind, missing asset and expiring Glade-only source. Include a leased range source and a separately bounded staged source whose registered fingerprint/backing bytes change after the first consumed range. Expected identities, dependent change footprints and cache hit/miss decisions are explicit. |
| `profile-output` | Two pinned profiles with distinct resolution, color/audio settings and output destinations. Change/remove a mutable profile name after Prepare while its admitted ID, version, digest and complete effective settings remain recorded. The oracle verifies stream count, codec/profile, dimensions, duration, frame/sample timing and final probe summary. |
| `publication` | Existing destination and provably equivalent path alias, an alias whose canonical equivalence cannot be proved, and a second successful generation. Exercise concurrent Glade and CLI processes against the same proven target. The manifest records original and replacement digests. |
| `graph-mutations` | Expected flat graph, binding and footprint records before/after an in-span ripple insert, registered-asset insert, undo/redo after reopen and binding-only rebind. Include unsupported placement/overlap and explicit substitution-policy choices; record exact split, shifted spans and dependent intervals. |
| `import-namespaces` | Two separate fresh offline imports of byte-identical graph/package content, each with its own journal and accepted-ID history; a missing-journal case and optional Glade source bridge. The oracle requires distinct, persistent, non-reused import IDs. |
| `invalid-wire` | Oversize/deep/invalid Taut messages, unsafe exact integers, unsupported semantic versions, wrong provenance branches and malformed negative result envelopes. No media task may be admitted. |

Fixtures for unsupported transitions/effects are rejection checks until their semantics and reference implementation are defined. Pin FFmpeg/FFprobe and every other candidate provider build in the run manifest. The software provider is the reference implementation; compare candidate decoded output at the operation's declared exact/proxy tolerance. Define pixel/color and audio numeric tolerances, including maximum A/V offset and encoder-delay accounting, per operation/profile before enabling that candidate, and version them with the test manifest. Exact identity, state, authorization and publication assertions have no tolerance. Mutation controls that omit a ripple split, drop an atomic binding, miss a dependent footprint, reorder a presentation frame or shift an audio window must each fail their fixture oracle.

## 4. Scenario matrix and pass conditions

Every scenario runs at the lowest applicable gate, then repeats across CLI and Glade where the boundary is relevant. The scenario IDs are stable names for implementation and evidence.

| ID | Runtime action and observable pass condition | Requirements / design seam |
| --- | --- | --- |
| RG-01 | Compare exact graph, binding and footprint records before/after an insertion inside an existing span: it splits that span, shifts later spans on the target track and extends the sequence atomically. A registered-asset insert creates the slot and binding in the same transaction; rejected unsupported placement, overlap or stale context changes neither journal. Exercise privileged full-record remove/reorder, undo/redo after reopen and explicit substitution-policy accept/reject cases. A binding-only rebind preserves graph digest, creates a new immutable set and invalidates every dependent interval (or marks full invalidation if closure is unproved). Round-trip keeps this meaning; only accepted edits advance contiguous revisions and in-flight renders keep old snapshots. | GVR-RDR-023–039, 065–068, 071–072 |
| RG-02 | Send duplicate, gapped, expired and out-of-order graph/binding/catalog changes, including ack before change. The client promotes only contiguous verified state, marks mirrors and previews stale on an unverified gap, and recovers by snapshot; no ack alone advances accepted state. | GVR-RDR-037–039, 065–068 |
| PV-01 | Request independent source preview before insertion at an exact indexed VFR frame. The result identifies asset version, stream and fingerprint, with no graph/binding identity. Change the catalog version/fingerprint while the response is held: the old frame is never displayed as current. | GVR-RDR-067, 069–070 |
| PV-02 | Request a late sequence frame while a full export is running. The plan includes only contributing layers, handles and decoder preroll; the requested visible frame is scheduled before bounded adjacent prefetch. Compare decoded pixels against the same time in a full reference render. No whole-sequence prerequisite occurs unless the effect declares earlier state. | GVR-RDR-040–043, 054 |
| PV-03 | Hold old preview responses while seeking, editing, rebinding, closing/reopening the project, cancelling and changing viewer. Only a response matching all current sequence or source identity, feed freshness and live lease can become current. Expired/replaced descriptors fail HTTP access or release; an old result cannot displace a new one. | GVR-RDR-041, 044, 069–070 |
| PV-04 | Return proxy then exact preview and apply memory/I/O pressure. Fidelity is accurately labeled; exact result replaces or remains distinguishable from proxy; bounded queues and fair admission protect exact requests. If service cannot be bounded, export admission defers/rejects with capacity rather than silently starving the viewer. | GVR-RDR-045–048, 054 |
| MD-01 | Run the implemented fade, gain, mix, layer composition, color conversion, encode and mux semantics through software reference and each advertising provider; add transition boundaries only when a versioned transition is supported. Compare B-frame/fractional-rate cut identities, boundary frames, resampled audio/channel windows, encoder-delay-adjusted A/V alignment and final profile probe to independent oracles at declared tolerances. A provider missing a semantic version rejects before execution. | GVR-RDR-043, 049–052; engine §3 |
| MD-02 | Fail hardware after Prepare. A permitted software fallback starts a new attempt with new dependent artifact keys, records provider/build, and cannot consume failed partial artifacts. With fallback forbidden, report typed failure and publish nothing. | Engine §§2–3, 6 |
| AS-01 | Resolve local, package and Glade-only sources. Offline CLI succeeds for local/package, and gives an actionable unavailable result for Glade-only media without a bridge. An authorized package materialization or bridge succeeds. After one pinned range has been consumed during export, change backing bytes and the registered version/fingerprint before the next range or lease renewal; test leased access and permitted bounded staging separately. The old request must fail without publication or require an explicit new binding set/new export, with no mixed-source artifact verified or reused. Lease expiry, missing range capability and changed input never silently substitute media or leak credentials/paths. | GVR-RDR-028–031, 055, 068; engine §4 |
| CL-01 | Render the same validated graph, binding set, profile and provider semantics through offline CLI and Glade. Normalized plan and decoded output agree at declared tolerance; provenance and authority fields remain branch-specific. Two fresh CLI imports of identical portable bytes receive distinct persistent local import IDs and independent accepted-ID histories; a missing journal cannot be recreated from a supplied old ID. Repeat with an optional Glade source bridge while retaining standalone provenance. Glade uses Taut for structured control and opaque descriptors, authorized HTTP ranges for raw bytes; CLI uses local/package bytes and does not need Glade. | GVR-RDR-056–063; engine §§1–2, lifecycle §1 |
| CL-02 | Cross-language Python/Rust/TypeScript encode/decode and malformed-input runs hit live service boundaries. Correlation, exact integer/rational values, size/depth limits and negative response payload rules survive round-trip; invalid wire is rejected before scheduling. | GVR-RDR-056–060, 072 |
| EX-01 | Submit same request concurrently, lose acceptance ack, expire the original destination reference, reopen host or restart CLI, then lookup and retry. Exactly one durable accepted ID/job/attempt is created; an authorized identical live retry returns the original job and originating context without destination/source revalidation or execution despite expiry; changed payload conflicts. Invalid pre-acceptance request reserves no ID. Governed and standalone namespaces never impersonate each other. | ExportJobs lifecycle §§2, 4 |
| EX-02 | In isolated stores or controlled state transitions, compare complete responses for byte-identical denied submits across another owner's live, retired and unused IDs; repeat with valid and intentionally invalid proposed payloads under inaccessible, unknown and retired scopes. All non-echo denial fields agree, job/diagnostic IDs are null, `replayed=false`, accepted-ID reads and work launches are zero. Then revoke/retire a scope at barriers before admission, lookup, status, cancel and event handoff: no post-revocation job fact, event or cancellation crosses the durable fence. Authorized grants see their entire scope history. | Owner-scope contract; lifecycle §§2, 4 |
| EX-03 | Cancel one of two jobs while the other runs, then crash/restart at queued, preparing, running and verifying states. Use both whole-tree termination and host-only death leaving a native child alive; on restart, match recorded PID and creation token, terminate the owned orphan, and never terminate a reused PID with a different token. Cancellation ack means requested only; final state is durable. Reopen reconciles processes, leases and artifacts before reuse; no unverified candidate becomes success. Other job proceeds independently. | Lifecycle §§2–4; engine §6 |
| EX-04 | Admit near quota, exhaust ordinary progress/journal space, force failure and restart. Reserved space records terminal/cleanup/publication reconciliation; new admissions return capacity. Inject write/fsync failure despite reserve: while storage is unavailable, success and ownership release are withheld. Restore writable storage and restart: durably reconcile process, artifacts, accepted ID, publication intent and generation. If work resumes, ownership remains until it reaches a reconciled terminal state; only then release ownership and admit a later claimant. Accepted IDs survive compaction and restart. | Lifecycle §3 |
| EX-05 | Crash immediately before admission commit: after recovery no accepted ID, job, attempt or tombstone exists, any tentative destination lock is reclaimed, and the same key can be freshly admitted. Crash immediately after commit/before ack: exactly one durable ID and recoverable job exist and the same key replays. For later crashes at tombstone conversion, publication intent, replacement, result commit and backup cleanup, assert one accepted ID or tombstone, old generation or verified new generation, and a partial candidate never replaces final bytes. An unresolved publication intent retains exclusive destination ownership until reconciliation; a fully reconciled terminal or pruned record releases it. After durable retirement, exact and changed-payload retries both return `retired_request` with null job ID and `replayed=false`, no source/destination validation or work; authorized lookup returns retirement with no snapshot. A later destination generation survives the old retry and any rollback. A proven active alias, including Glade versus CLI processes, returns destination-busy before launch; an alias whose canonical identity cannot be proved rejects before launch or publication intent. | Lifecycle §§2–4; engine §6 |
| EX-06 | Run a batch with shared graph but different profile, range, destination and binding set. Each item has separate immutable job/result/verification. Verified subresults reuse only matching semantics/toolchain keys; cache poisoning and one-item failure do not change another result. Partition boundaries, audio timing and output probes match single-export references. | GVR-RDR-047, 049–055 |

After profile resolution and Prepare, mutate or remove the named host profile entry; repeat on a retry. Run, retry, verification and publication must retain the admitted profile ID/version/definition digest and complete effective settings, or fail with a typed mismatch and no publication. An implementation that rereads the mutable name fails this check. For every final export, assert the candidate is fully rendered at that pinned final profile, independently probed, durably recorded and published under destination ownership before reporting success. A preview artifact or native-process exit code is never sufficient evidence.

## 5. Fault schedule and state assertions

The controller publishes named barriers: `before_admission_commit`, `after_admission_commit_before_ack`, `after_profile_prepare`, `before_attempt_record`, `after_attempt_record_before_tool_launch`, `after_tool_launch`, `after_first_pinned_source_range`, `after_candidate_write`, `before_probe`, `after_probe_before_intent`, `after_publication_intent`, `after_replace_before_result_commit`, `after_result_commit_before_backup_cleanup`, `before_tombstone_conversion`, `after_tombstone_conversion`, and `before_positive_response_handoff`. Add scope-grant and event-delivery barriers before authorization-sensitive reads/actions and at handoff. These are conceptual seam names; implement them as one controlled test hook interface at production transition points, without changing the state machine.

At each applicable barrier, run normal continuation, whole-tree kill/restart, host-only crash where relevant and repeat/retry variants. Record the durable accepted-ID entry, journal reservation, job state, process creation token, owned spool paths/leases, destination identity/generation, backup and result digest both before and after recovery. State conservation depends on the commit boundary: before admission commit there is no durable accepted ID, job, attempt or tombstone and tentative ownership is reclaimed; after commit an accepted ID and owned resources remain reconciliable. Every launched resource has a durable owner, and neither success nor ownership release is inferred from an incomplete write. Inject proven and unprovable aliases and concurrent claimants with barriers rather than racing by sleep. After a transient storage fault, test both fail-closed behavior while unavailable and progress to durable reconciliation after restoration. A failure report includes the minimal seed, barrier and resulting state trace for reproduction.

## 6. Performance and fairness gate

GVR-RDR-048 requires budgets before release; this draft deliberately sets no invented latency numbers. Pin at least one interactive reference machine and one constrained machine, OS/toolchain, fixture complexity, output profiles and resource limits. Establish numeric cold seek, warm seek, exact parked frame, first usable post-edit frame, sustained playback with concurrent export, export throughput and preemption/defer deadlines before declaring the release gate active.

Measure request-to-first-usable and request-to-exact latency from client submission through decoded presentation, not only planner time. Capture cold/warm cache separately, early/middle/late seeks, rapid scrub, edit/rebind invalidation, one export and batch pressure. Record median and tail latency, deadline misses, decode queue/spool maxima, interactive progress and export progress across repeated seeded runs. The gate passes only when every correctness invariant holds, configured resource caps are respected, the agreed latency/deadline budgets pass on the pinned machines, and exports make fair progress when capacity permits. The run record states sample count, warm-up, cache state, machine load and variance policy. Any budget change needs a new versioned baseline and rationale, not a silent threshold update.

## 7. Evidence and implementation order

Each run emits a machine-readable manifest and a short human report: renderer and GWZ root commits, Taut source/compiler/runtime versions, generated-binding versions, provider executable/build digests, profile definitions, OS/hardware/resource limits, fixture digests/seeds, scenario ID, driver/client branch, injected barrier, start/end state, oracle/tolerance version, metric distribution, result, and hashes of retained synthetic output/trace artifacts. Redact credentials, private locators and source media outside synthetic fixtures. Keep failed reproducers and crash journals in an access-controlled test artifact store; reports cite their IDs without embedding secrets.

Implement in four slices with a demonstrable exit for each:

1. **Media vertical slice:** deterministic fixtures, core driver, software provider, late seek and one verified offline CLI export. Exit: PV-02, MD-01 reference path, AS-01 local/package and CL-01 offline half pass with actual media.
2. **Glade and wire slice:** Taut drivers, cross-language round-trips, source/sequence preview, lease-aware HTTP, Glade-only resolver. Exit: RG-01/02, PV-01/03, AS-01 Glade half and CL-01/02 pass.
3. **Durability slice:** persistent supervisors and barrier controller. Exit: EX-01–05 pass for governed and standalone branches where applicable; no unresolved owned artifacts or destination intents.
4. **Parity and load slice:** candidate providers, batch/cache cases and measured scheduler gate. Exit: PV-04, MD-02, EX-06 and versioned GVR-RDR-048 budgets pass on pinned machines.

Before implementing each slice, convert its rows to executable test cases with exact fixture digests, expected status envelopes, numeric media tolerances and runner commands. Review this test design against the accepted integrated contract first; later implementation results are a separate evidence record and require their own acceptance decision.
