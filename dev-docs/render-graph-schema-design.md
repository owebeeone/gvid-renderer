# GVid flat render graph and Taut contracts (draft v0.2)

**Status:** Draft design baseline for the first implementation. The governed schema is [`../ir/gvid_render_graph.taut.py`](../ir/gvid_render_graph.taut.py); regenerate Python, Rust and TypeScript with [`../regen-taut-protos.py`](../regen-taut-protos.py). The [ExportJobs lifecycle amendment](export-jobs-lifecycle-design.md) controls the revised export admission, namespace and retirement rules until its own review decision. This pass adopts [GVid Taut Proto Feedback](../../dev-docs/GvidTautProto-Feedback.md). No client consumes v0.1, so v0.2 is a direct revision, not a migration promise.

## Decisions and ownership

| Concern | v0.2 decision |
| --- | --- |
| Accepted graph | A small flat map document: `sequences`, `tracks`, `nodes`, `edges`, `slots`, keyed by stable IDs. The browser may edit a JSON-shaped tentative projection in memory; the project authority alone publishes accepted immutable revisions. |
| Graph mutation | `EditBatch` and `RenderGraph.apply` are privileged graph-wide maintenance/journal interfaces. A browser never authors them. One batch may affect several sequences. |
| User edit | Version 1 `Editor` intents carry explicit `sequence_id`. The authority validates Insert, Undo and Redo, then lowers each accepted intent to one atomic graph batch. |
| Media catalog | Version 1 `MediaCatalog` gives a typed read-only view of registered asset versions, fingerprints and stream origins before an asset is placed in a graph. |
| Media binding | Version 1 `AssetBindings` owns immutable binding-set IDs and slot-to-registered-media mappings. Rebinding can change pixels without changing graph revision. |
| Preview | Version 1 `Preview` owns frame requests, cancellation, result identity and display-resource leases. A sequence result is one composited resource, not a list of source frames interpreted by the UI. |
| Export jobs | Draft version 1 `ExportJobs` carries pinned export submissions, per-job events, status and cancellation. It is a boundary contract, not a running job supervisor. |
| Session | Version 1 `ProjectAuthority` owns the open incarnation and writer lease. These identities are outside `GraphSemantics`. |
| Transport | Structured commands, events, descriptors and failures use Taut. Encoded media bytes use authenticated HTTP range access. Opaque preview resources are resolved by the privileged host, not by graph paths. |

The graph is renderer-neutral editorial state. A renderer reads an accepted revision and binding set and derives a plan for a requested interval or export. It never writes editorial state. The candidate saved format remains deterministic Taut CBOR plus an accepted-command journal; a share package may include a readable JSON projection and separate binding manifest. The final downloadable format still needs size, decode, migration and browser/native measurement under GVR-RDR-061.

## Flat graph and exact time

`GraphSnapshot` uses schema `0.2` and semantic registry version `2` in the fixtures. The map key equals each record's `id`; IDs are collision-resistant, unique across entity maps and never deliberately recycled in a project history. An imported standalone snapshot without its journal starts a new graph identity. Names and UI selection are not semantic IDs. A graph has one or more sequences, ordered tracks, typed nodes and edges, logical asset slots, and output roots. Cycles, dangling references, cross-sequence edges, invalid port/media matches and unreachable nodes are invalid. A source or title node belongs to a track and has a half-open timeline range. Processing nodes have declared ports in the registry. The graph has no machine paths, URLs, credentials, executable arguments or cached frames.

`Rational` is reduced signed numerator/positive denominator in seconds. Numerator and denominator are bounded by signed 64-bit and JavaScript's exact integer range (`2^53-1`); denominator also has product limit `10^9`. Checked or BigInt intermediate arithmetic reduces before encoding. Timeline and source ranges are distinct `[start,end)` intervals. Source stream times are presentation times relative to a registered stream origin, not decode order or nominal frame number. Speed is positive in v0.2, and source duration under speed must equal the timeline span unless a future explicit trim/pad policy applies. VFR mapping, output rounding, reverse/freeze and nested sequences remain time-model work.

`Node.kind` and the optional typed payloads form an application-validated discriminated union: exactly the matching payload is non-null, except `silence`, which has none. `ParamValue` follows the same rule. Taut has no native `oneof`; codec success alone does not validate graph semantics. Unknown required node/effect/parameter versions fail closed.

The semantic digest hashes a normalized `GraphSemantics` Taut message: graph schema and semantic versions, sequences, tracks, nodes, edges and slot expectations. It excludes graph/project/revision identity, bindings, authority incarnation, leases, selection, caches and history. Bound consuming identities include binding-set ID/revision and fingerprints, effect/toolchain versions, pinned profile ID/version/digest, fidelity and requested range. A content-addressed subresult can be mapped across binding sets only after all contributing slot identities and semantics are revalidated and the consuming set identity is recorded separately. An undo can produce a new revision with an earlier semantic digest.

## Initial playable port registry

The following built-ins are valid before a general effect/port registry exists. All edges stay within one sequence. Ports are case-sensitive. A source with media `video` exposes `video`; an audio source exposes `audio`. The initial subset routes each source once to its track selector; future registry entries may allow fan-out.

| Node | Incoming port | Outgoing port | Rule |
| --- | --- | --- | --- |
| `source` | none | `video` or `audio` | Its exact timeline range and track determine when it is active. |
| `composite` with `blend_id="timeline.select.v1"` | `item`, zero or more same-media source outputs | `output` | `track_id` is required. Spans on that track must not overlap; order is by exact start time then node ID. `Edge.order_key` is null. A gap yields transparent video or silent audio. |
| `composite` with `blend_id="layer.stack.v1"` | `layer`, zero or more track-selector outputs | `output` | `track_id` is null. One input per enabled track; edge `order_key` equals that track's unique `Track.order_key`. Video is composited bottom to top; audio is mixed in declared order. |
| `output` | `input`, exactly one | none | The node is the sequence's matching root. It fills final video transparency with black and final audio gaps with silence. |

A single-track sequence may connect its selector directly to the root. A multi-track sequence routes selectors through one layer stack. The initial subset requires enabled tracks; a disabled-track retention and routing policy remains open. Source spans on the same track may touch at an endpoint but must not overlap; an overlap requires an explicit future transition/layer policy. The sequence range may start at a nonzero rational time. Selectors cover the sequence range; blank intervals are implicit, not fake source nodes. No effect or transition port is accepted until its registry entry defines media, cardinality, temporal handles, overlap and preview/final semantics. This rule keeps the first two-clip graph deterministic while leaving richer effects open.

The Taut-serializable, baseline-validated [two-clip fixture](../fixtures/two_clip_graph.json) has two timed sources on one track, a gap, a selector and an output root. The [ripple result](../fixtures/ripple_insert_graph.json) splits the first source, inserts a new span, shifts the later clip and extends the sequence in one accepted revision. The [lowered batch](../fixtures/ripple_insert_batch.json) is authority-produced; the browser sends `InsertSourceSpan` instead. A split retains the original ID for the left span and allocates a new right-span ID. The ripple policy in v0.2 affects only the target track and extends the sequence; linked tracks, locked tracks, transitions and multi-sequence ripple reject with an actionable status.

## Graph authority, replay and acknowledgements

`RenderGraph.snapshot` returns `GraphSnapshotDelivery`: snapshot at revision N plus the current `authority_incarnation_id`. `RenderGraph.changes(project,graph,incarnation,after_revision=N)` is a retained Taut `log`. The first event is `ready`, giving the current revision and earliest replayable revision. The host atomically attaches the subscriber and reads the retained log, then sends every accepted change N+1 onward in order before live changes. Exactly one accepted `AcceptedChange` advances each graph revision by one; no-op commands do not advance it. This makes snapshot N a replay anchor even when an edit commits between snapshot and subscription. A ready event is not a change.

A `change` event contains exactly one `AcceptedChange`; its project, graph and revision must match the event; the event supplies the current incarnation, and `from_revision` must equal the mirror's current revision. Equal-revision duplicate delivery with byte-identical change is ignored; a different duplicate, skip or reversal is a protocol failure and forces refresh. An expired cursor, queue overflow, invalid epoch or unavailable replay emits `recovery_required` with a reason and closes; the UI marks the mirror and preview stale immediately, obtains a new snapshot and resubscribes. The first-available revision is explicit; no silent gap is allowed. The server emits heartbeat at most every five seconds of inactivity; a client with no event for fifteen seconds marks the stream stale. The host caps each subscriber queue at 128 events or 8 MiB, then sends recovery-required and closes. Retention duration is configurable, but expiration is always explicit. The generic Taut `log` shape alone does not implement these GVid guarantees; the host adapter must.

`EditBatch` contains project, graph, command, expected revision, undo group and typed full-record put/remove operations. It can span sequences and is the durable journal record. `RenderGraph.apply` accepts an `ApplyGraphBatch` envelope with the batch, current authority incarnation and writer capability; only the privileged project authority may call it. The credential-bearing envelope is never persisted. The authority checks authorization, size/depth, command identity, expected revision, typed payloads, exact ranges and the entire candidate graph before durably accepting a batch. A remove must remove incident edges in the same batch. Failure changes neither graph nor journal. Reordering replaces track or ordered-edge records. The journal records the accepted batch and inverse records for undo, never writer capabilities or preview leases.

`EditAck` echoes project, graph, current incarnation and command; `AcceptedChange` echoes project and graph, while its delivery event carries the current incarnation. Idempotency is keyed by `(project_id, graph_id, command_id)` across reopenings. The project authority compares a canonical logical command payload that excludes the session capability and incarnation. An identical retry returns the original outcome and revision with `replayed=true` and the current delivery incarnation; a changed logical payload under the same key is invalid. A replay does not create another change. An ack may arrive before its feed change. The UI keeps the gesture pending and does not promote its graph mirror or preview until it applies the contiguous change or verifies a fresh snapshot at that revision. An ack is not itself a snapshot.

## User-facing Editor contract

`Editor.insert_source_span`, `editor.undo` and `editor.redo` use contract version 1 and explicit project, graph, sequence, authority incarnation, command ID and expected graph revision. Insert additionally names target track, exact timeline insertion point, placement mode, exact source range, positive speed, stream, expected binding set, undo group and writer capability. It has exactly one asset selection: an existing bound `slot_id`, or a registered `asset_id` plus immutable `asset_version_id`. In the latter case the authority creates a logical slot and binding in one transaction with the graph edit, increments both graph and binding revisions, and emits one change on each feed. `EditorAck` reports both revisions, binding set and created slot ID. The UI waits for both contiguous changes or verifying snapshots before previewing the new asset. An existing-slot insert changes only the graph. Undo/Redo target an undo group and require the current revision, binding context and lease. The project authority validates the intent, lowers it to one graph-wide `EditBatch`, commits it atomically and emits the required changes.

The initial supported placement is `ripple_track` on an unlocked target track whose affected nodes use the initial port registry. `overwrite_track` is a reserved typed option and returns `unsupported_ripple_scope` until its policy is designed. The authority rejects stale graph, stale binding, invalid range, locked track, unsupported ripple scope, unauthorized writer, invalid command, future schema and recovery-required with distinct `EditorStatus` values. `EditorAck` echoes the full context, accepted graph and binding revisions, binding set and optional new slot. The `replayed` flag means an exact retry returned the original outcome; it does not create another revision. On replay after reopen, the ack uses the current incarnation but retains the original outcome revisions and binding set, which the UI must verify against current snapshots. `editor.history` returns an authority-owned `HistoryState` with current revision and explicit can-undo/can-redo flags and labeled eligible undo/redo groups for a sequence, including after reopen. The flags equal whether the corresponding eligible group list is nonempty; a stale history revision must be refreshed before enabling controls. Undo and redo are new validated intents at the current revision with fresh command IDs and inverse batches. The authority stores a canonical intent hash without session credentials for retry conflict detection.

## MediaCatalog and AssetBindings contracts

`catalog.snapshot` returns registered asset versions, fingerprints, display names, explicit online/missing/changed/offline status and diagnostic reference, plus stream media/duration and exact PTS origin without requiring a graph slot. A stream's `frame_count` and opaque `frame_index_id` are present only when indexing is ready; `index_status` reports pending or failed work. `catalog.frame_at_index` resolves a validated frame index to an exact stream presentation timestamp and fingerprint for VFR stepping and In/Out marks. The UI never computes frame position from duration or nominal fps. The asset-library source viewer can select an immutable version before insertion.

`catalog.changes` uses the graph feed's ready/replay/heartbeat/recovery rules, with one event per catalog revision; a missing, changed or newly indexed asset is an upsert with explicit status. On a gap or stale feed the UI marks catalog and source previews stale, fetches a new snapshot and resumes from its revision. The project media service owns registration and the event log. This is a typed catalog contract, not a claim that asset ingestion or indexing is already implemented.

`BindingSnapshot` is a separate version 1 document with immutable `binding_set_id`, monotonic `binding_revision` and a keyed slot map. Each `AssetBinding` records registered asset/version, selected stream, content fingerprint, media and exact duration; paths and credentials remain in a privileged local registry. A successful `bindings.rebind` checks graph and binding expectations, validates the replacement and explicit duration/frame-rate/aspect/channel/missing-range policies, allocates a new immutable set ID, increments binding revision and emits one `BindingChange`. The graph revision and semantic digest do not change. Unsupported policies reject; values in an enum do not imply every implementation supports them.

`bindings.changes` uses the same ready/replay/heartbeat/recovery rules as graph changes, with one event per binding revision. A binding-only change carries changed slot IDs and a conservative `ChangeFootprint` computed from graph dependencies. If closure cannot be proved, `full_invalidation` is true. Every preview/cache/export identity includes binding-set ID and content fingerprints: equal duration with different bytes is a cache miss. A prior export retains its original set ID and evidence.

## Preview and authority contracts

`preview.source_frame` takes `SourcePreviewRequest` for a registered asset version and stream from `MediaCatalog`, its expected content fingerprint, exact source presentation time, project incarnation, request/viewer/cancel-group IDs, fidelity and bounded size. It requires no graph, sequence, slot or binding set. A changed or missing version returns `stale_asset` or a failure; the source viewer can inspect library media before insertion. `preview.sequence_frame` takes `SequencePreviewRequest` with project/graph/sequence, incarnation, accepted graph revision, binding set and revision, exact timeline time and the same request controls. The renderer traverses backward from the requested output/time, expands transition/effect handles and decode preroll, renders that interval first, then bounded adjacent prefetch. It never needs to render from sequence time zero just to show a late frame.

`SourcePreviewResult` echoes registered asset/version/stream and fingerprint; `SequencePreviewResult` echoes graph/binding identity and plan ID. Both report actual time, fidelity, status, optional diagnostic and at most one opaque `ResourceDescriptor`. A ready sequence result is the already composited display resource for every active layer. The UI never evaluates graph nodes into pixels. The descriptor has bounded dimensions/bytes and a lease ID with expiry; the host resolves authorized resource access, and `preview.release` ends the lease. `preview.cancel` targets a request/viewer/cancel group; cancellation is best effort, and a late result is discarded unless every current identity field still matches. No raw encoded media bytes are placed in Taut messages.

`authority.open` returns a project-open incarnation and explicit `ready`, `read_only_future_version`, `recovery_required` or `closed` state. `authority.acquire_writer` grants an opaque lease/capability only for the current incarnation and authorized client. Only one active writer is allowed per project in v0.2. Lease expiry or project reopen makes old capabilities invalid; receivers do not equate equal numeric revisions across incarnations. Writer capability is a privileged credential: do not log, persist in the portable graph, or expose it to renderer workers. Authentication, lease renewal/takeover and recovery storage mechanics belong to the project-host implementation; a client without a valid lease is read-only and must not call a frame globally current.

## ExportJobs boundary contract

The governed schema adds `export.submit`, `export.lookup`, `export.events`, `export.status` and `export.cancel`. `ExportJobContext` identifies request, project, graph, sequence, accepted revision, immutable binding-set ID/revision and pinned profile ID/version/definition digest. Exactly one provenance branch is valid: `governed_host` has an authority incarnation and no local import ID; `standalone_import` has a local import ID and no host incarnation. The Glade gateway accepts only the governed-host branch after checking current project read authority and an opaque destination reference with write authority. A local CLI machine protocol may use the standalone branch after validating a portable graph and binding manifest; it cannot claim a host incarnation. Neither provenance ID changes the semantic plan for identical inputs.

Submit includes an exact half-open export range, fallback policy and explicit `fail_if_exists` or `replace_existing` destination policy. The destination reference is an opaque host/local registry handle, never a path, URL or credential in the portable graph or job result. The durable accepted-ID key is `(governed_host, project_id, request_id)` for Glade and `(standalone_import, local_import_id, project_id, request_id)` for a CLI journal. Project and local import IDs are stable and never reused after deletion. After provenance-specific current-caller authorization, the receiving service checks this index before profile/source revalidation, destination-reference expiry or destination-owner acquisition. Idempotency compares a canonical logical payload containing project/graph/sequence, graph/binding revision and set, exact range, profile identity, original destination reference and policy, and fallback policy; the governed delivery incarnation is excluded. An identical retry of a live record returns the original job with `replayed=true` even after reopen or reference expiry; a changed substantive payload returns `idempotency_conflict` and never starts another job. Before pruning a full job record, its index entry becomes a durable compact tombstone that survives for the namespace lifetime. A submit using that ID returns `retired_request` without starting work.

A new governed-host request ID must have a current project incarnation and host-authorized destination reference. A new standalone-import ID must have an existing local import/journal, validated portable graph and bindings, and locally authorized destination reference; it has no host incarnation. The receiving service resolves the named profile and checks that ID/version/digest matches the immutable effective definition; it resolves a retained binding set and validates the accepted revision and source identities. A shared cross-process publication coordinator then obtains an exclusive canonical-destination owner and atomically records the request, destination binding, stable job ID and lookup index. A concurrent claimant for the same key re-reads the durable winner and cannot start another job. A competing active destination request returns `destination_busy` before another job starts. A crash can release its OS lock, but a durable unresolved intent blocks a new owner until reconciliation under that lock. Later replacement requires explicit policy and yields a new destination generation; a historical export record retains the generation it committed.

`export.lookup` uses project and request ID, plus exactly one caller branch: a current host incarnation or persistent local import ID. A governed caller needs current project/job read authority; a standalone caller needs access to the same local import and journal. It reads the durable index and returns the original job ID, immutable originating context and status snapshot while the full record exists, without re-executing or checking original destination expiry. Once the record is pruned, an authorized caller receives `retired_request` and no snapshot. Unknown and unauthorized requests return the same unavailable status; an invalid current caller has a stale-context status. A lost submit acknowledgement is recoverable while the retained job record exists; after retirement, the caller can establish that it was accepted without accidentally rerunning it. The old job result remains historical and cannot become the new viewer's current export result. The [ExportJobs lifecycle amendment](export-jobs-lifecycle-design.md) specifies authorization and crash-safe retirement order.

`export.events` is a per-job retained log. A ready event states current event sequence and first replayable sequence; subsequent state/progress/warning events have contiguous sequence numbers. Progress is a checked rational fraction in `[0,1]` and may be coalesced without skipping sequence numbers. Heartbeat, duplicate, gap, expiry, queue overflow, reconnect and recovery-required behavior follow the graph feed's bounded delivery rules; an unverified gap forces a status query and subscription reset. Every event echoes the immutable context and job ID. State transitions are queued, preparing, running, verifying, then succeeded/failed/cancelled/interrupted; only succeeded carries a verified export result. Failure, cancellation and interruption carry a diagnostic ID. Terminal state and last sequence are durable and queryable after restart while the full job record is retained; after pruning, request-ID lookup reports retirement without an outcome snapshot. A result from an old incarnation remains a historical job result and cannot replace a new session's current UI state.

`export.cancel` names project, job and command ID plus the caller's current host incarnation or local import ID. Authorization is checked against that job, and repeated cancellation is idempotent. Its acknowledgement means only that cancellation was requested; a later terminal event or status snapshot states the outcome. Unknown, unauthorized, stale and already-terminal targets are distinct. `export.status` permits an authorized caller with a known job ID to recover state after a feed gap; `export.lookup` handles a lost acknowledgement. The export result exposes verified record/artifact IDs, destination generation, and a typed, bounded probe summary and digest, never raw probe text, encoded bytes or a machine path. The host implementation must enforce the discriminated provenance and event payload rules after Taut decoding; generated bindings alone do not do so.

## Limits, evolution and acceptance

Taut limits graph/message depth to 16 and encoded length to 16 MiB as upper wire guards; host product limits for nodes, edges, strings, degree, parameters, resource descriptors, export probe summaries and exact arithmetic must be lower and measured. Every privileged boundary validates identifiers, schema/contract version, resource access and semantics after Taut decode. The version 1 Editor, MediaCatalog, AssetBindings, Preview, ProjectAuthority and ExportJobs services are contracts, not running services. No production UI conformance is claimed from generated bindings alone.

This is virgin protocol ground: v0.2 directly revises v0.1, keeps useful field tags but makes no compatibility claim for old generated clients. Once used durably, tags/names must be reserved on retirement and additive fields need Taut's `MISSING_OK` when new readers must accept old bytes. The pinned generator is `taut-proto==0.10.0`; the golden corpus and cross-language parity gate must be pinned before a production freeze.

Required implementation evidence:

1. Taut encode/decode and golden bytes for graph snapshots, correlated accepted/rejected/retried/stale acks, contiguous changes and separate binding/preview messages; Python, Rust and TypeScript parity.
2. Snapshot N, concurrent commit, subscribe after N, replay through N+1; exact retry, changed-payload conflict, cross-project same ID, duplicate, gap, expiry, queue overflow, reconnect and ack-before-change cases.
3. The two-clip and ripple fixtures serialize; valid nonoverlap and gaps render deterministically; overlap, wrong port/media, dangling edge and cycle reject atomically.
4. Binding-only rebind leaves graph revision unchanged, invalidates affected preview/cache, and misses cache when bytes change at equal duration.
5. Catalog replay and exact VFR frame-index lookup remain fresh across missing/changed media. Late source and layered-sequence seeks produce only identity-matched, lease-valid results; cancellation and expiry prevent stale display.
6. Typical and large graphs are measured for snapshot bytes, browser projection/edit latency, encode/decode time and feed catch-up. Product limits and retention are set from those results.
7. ExportJobs messages round-trip and cross-language bindings agree for two concurrent jobs with different graph/binding contexts, idempotent retry, out-of-order progress, cancellation of one job, gap/status recovery, request-ID lookup after a lost accepted acknowledgement, changed-payload conflict, destination-busy collision, retired-request submit/lookup and old-incarnation result after reopen. A fresh offline CLI import with no host incarnation must submit and recover; a stale governed incarnation must fail. After a job record is pruned, exact and changed retries of its ID must create no job and cannot overwrite a later destination generation. The host semantic validator rejects invalid provenance branches, unauthorized tombstone discovery and success without a verified result.

Open design work: VFR/PTS and output rounding; full port/effect registry and automation; order-key rebalance; portable title styles; reverse/freeze and nested sequences; disabled-track retention/routing and cross-track ripple/transition policy; asset substitution implementation; catalog registration and index storage; generated TypeScript packaging for gvid-ui; snapshot cadence and final download format. The initial built-in port rules above are a normative v0.2 subset, not a claim that these later cases work.
