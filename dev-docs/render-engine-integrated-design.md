## 1. Precedence and closed architectural choices

The requirements state product obligations. The root architecture and sequence-preview ADR assign service ownership. The graph schema and Taut source define wire and edit-graph shapes. The engine design defines core planning, provider, resolver, scheduler and client boundaries. The ExportJobs lifecycle design defines durable admission, job state, recovery, publication and ID retirement. The accepted owner-scope design revises governed ExportJobs request identity, grant visibility, negative-response shape and the revocation fence. When an older ExportJobs sentence conflicts with the owner-scope design, the owner-scope rule controls; when a wire name or tag is in question, the Taut source controls. A historical NO-GO review report is evidence of a defect at its cited tuple, not a live alternative contract.

The project service alone accepts graph edits and persists revisions. The editable graph remains a small, flat, portable description: nodes, edges, tracks, sequences and slots are changed by Taut edit operations, while immutable asset bindings and accepted revisions identify a render. Render workflows are derived, disposable task DAGs; they are never serialized back into the portable graph. The user can download, share, reload and rebind the graph without carrying local paths, access tokens or renderer command lines.

## 2. Rendering and client boundary

The headless core validates immutable graph/binding/profile inputs, lowers them into typed tasks, selects providers by declared semantic capability, and executes through an injected scheduler and asset resolver. A provider implements the same assess/execute/evidence contract for decode, composition, fades, audio operations, encode, mux and probe. Unsupported semantic versions fail explicitly. The software reference path establishes the baseline; hardware fallback creates a new attempt and cache identity. The core does not own Taut endpoints, HTTP serving, Glade authentication or CLI parsing.

The Glade adapter owns authenticated Taut commands, events and resource descriptors, plus an authenticated HTTP endpoint for raw media bytes. The standalone CLI loads a portable graph/package and local binding manifest, runs the same core with a local scheduler and journal, and requires no Glade network service for local or packaged assets. A Glade asset bridge is an optional resolver that supplies authorized source access, never a substitute render engine or a fabricated host incarnation. Structured cross-component communication uses Taut; encoded video/audio bytes travel as raw HTTP media or local file/package bytes.

The asset resolver pins registered asset version, selected stream and fingerprint. It may return range-capable access, a leased source handle or explicitly authorized bounded staging. A Glade-only source can be exported by authorized materialization into a package or by the configured Glade resolver bridge; a missing or expired source yields an explicit result. Credentials and machine-local locators do not enter the graph, render plan, cache key, portable package manifest or tool provider. Rebinding to new assets creates a new immutable binding set and export record while preserving the graph revision.

## 3. Interactive and batch execution

Sequence preview produces one composited video resource for the requested frame or finite range. A seek plans backward from the requested output through only contributing graph nodes, including source preroll and declared temporal handles. It schedules the requested visible result before bounded adjacent prefetch; sequence-start rendering is required only for an effect that explicitly declares earlier state. Source preview may operate on a registered asset without a graph. A sequence result echoes its request, accepted graph revision, binding set and fidelity; the client rejects it when any of those no longer match the current sequence viewer. A source result instead echoes its request, registered asset/version/stream, expected content fingerprint and fidelity, with no fabricated graph revision or binding set. The source viewer rejects it if the current catalog version or fingerprint differs. Both branches recheck their applicable live authority before presentation.

A shared scheduler admits interactive preview fairly against export and batch work under CPU, memory, disk, I/O and accelerator limits. Batch exports may share verified intermediate artifacts only when graph, bindings, profile semantics, toolchain and capability identities match. Each output retains an independent immutable request, job, destination policy, verification and evidence record. A disposable preview artifact cannot be promoted to a completed export without final-profile rendering, probe verification and publication.

## 4. ExportJobs integration

The governed host and standalone import are separate provenance branches. Governed accepted IDs use `(governed_host, project_id, owner_scope_id, request_id)`; offline CLI IDs use `(standalone_import, local_import_id, project_id, request_id)`. A host-minted owner scope is stable and non-reused. Its submit grant includes visibility to all accepted IDs and jobs in that scope. The current host incarnation is delivery authority, not part of either logical render plan or governed idempotency key. An inaccessible scope is denied independently of accepted-ID occupancy. A caller authorized for a scope may replay a live request exactly, receive conflict for a changed payload, or receive a retired-ID result after durable job pruning.

Grant revocation and scope retirement share a durable ordering fence with accepted-ID lookup, admission, job-ID status/cancel classification, cancel action and positive transport handoff. Revocation ordered before an action or disclosure blocks it; retirement ordered before admission blocks a new job. An authorized accepted job reserves its accepted-ID/tombstone slot and bounded journal capacity before acknowledgement. Nonterminal or unreconciled jobs retain full records. Terminal pruning atomically converts the live ID to a permanent scoped tombstone. A crash cannot make an accepted ID reusable. Canonical destination ownership, probe verification and publication intent prevent an old retry from replacing a newer generation.

## 5. Acceptance scope and proof matrix

This gate decides **design coherence and contract sufficiency** across the package above. It should explicitly re-trace the two original engine NO-GO counterexamples (offline CLI provenance and accepted-ID retirement), the later project-wide request-ID privacy counterexample, and the revocation races found during owner-scope review. It also attacks interactions with flat graph mutation, asset binding, on-demand preview, provider semantics, Glade/CLI separation and batch publication. An accepted result would authorize implementation against the settled design; it would not claim completed services.

| Seam | Design proof to check | Runtime evidence still required |
| --- | --- | --- |
| Graph and assets | Flat Taut edits never mutate a render in flight; graph sharing and rebinding remain reproducible. | Graph/editor conformance, resolver identity and lease failure tests. |
| Preview and batch | Requested frame has a bounded dependency slice; source and sequence results use distinct freshness identities; fair admission and cache identity preserve exact semantics. | Source-version/fingerprint and sequence-revision/binding stale-result tests; seek/latency, starvation and output parity measurements on reference hardware. |
| Providers | Typed semantic versions and explicit conversion/fallback prevent hidden tool defaults. | Provider conformance fixtures and final probe tests. |
| Glade and CLI | Same core receives distinct authority/provenance; media bytes and structured messages stay on their assigned transports. | Offline CLI, Glade gateway and cross-language Taut integration tests. |
| ExportJobs | Scoped ID replay/retirement, durable reserve and revocation ordering exclude the recorded privacy and overwrite traces. | Concurrent admission, crash/restart, quota, cancellation and destination-generation tests. |

The current reference suite checks the draft Python wire fixtures and selected semantic validators. Generated Rust and TypeScript types exist, but full runtime parity and host-store behavior remain implementation gates. The review must not turn a specified test into a claim that it already ran.
